# Осмотр авто — лабораторная работа №3

Приложение для заполнения данных автомобиля, выбора фотографии и ведения истории осмотров. Frontend: React, TypeScript, Material UI, React Router, Vite. Backend: Python, FastAPI, PostgreSQL, SQLAlchemy.

## Запуск frontend

Требуется Node.js 22.12+ или 24 LTS.

```powershell
cd frontend
npm ci
npm run dev
```

Открыть адрес, указанный Vite в терминале. Для проверки production-сборки:

```powershell
npm run build
npm run preview
```

## Лабораторная работа №3

Frontend разделён по назначению:

- `src/app` — маршруты приложения, общее состояние автомобиля и фотографии, стили.
- `src/pages` — страницы начала, автомобиля, фотографии, входа, регистрации и истории.
- `src/features` — формы автомобиля и аккаунта, выбор фотографии, сохранение осмотра.
- `src/entities` — типы автомобиля и осмотра, проверка автомобиля, репозиторий осмотров.
- `src/shared/ui` — общий макет и компонент состояний данных.
- `src/main.tsx` — точка входа, подключение темы Material UI и маршрутизатора.

Используется упрощённая структура FSD. Страницы собирают пользовательские действия, действия используют сущности, общие компоненты не зависят от страниц. Полное соблюдение FSD не требуется. Состояние полей хранится через useState, побочные действия — через useEffect. Пропсы и данные типизированы TypeScript.

## Сценарии

1. На главной странице выбрать «Начать осмотр».
2. Заполнить марку, модель и год. Пустые поля и год вне диапазона от 1900 до текущего блокируют переход. Тип кузова необязателен.
3. Выбрать JPG, PNG или WebP размером до 10 МБ. Фото можно заменить или удалить, перед сохранением отображается предпросмотр.
4. Добавить примечание длиной до 1000 символов и сохранить осмотр. Во время сохранения кнопка заблокирована.
5. В истории найти осмотр по марке, модели, году или примечанию. Удаление требует подтверждения, диалог можно отменить.
6. Перейти к входу или регистрации. Формы проверяют почту, пароль и его подтверждение.

Прямой переход на `/photo` без заполненного автомобиля перенаправляет на `/car`. Неизвестный адрес перенаправляет на главную. Значения автомобиля и выбранный файл сохраняются при переходах внутри приложения, но сбрасываются при обновлении страницы.

## Данные и ограничения

В третьей работе frontend использует локальный репозиторий. В localStorage под ключом `car-damage-lab3.inspections` сохраняются данные автомобиля, имя фотографии, примечание, идентификатор и дата осмотра. История сохраняется после перезагрузки и доступна только в том же браузере и на том же адресе. Содержимое фотографии не сохраняется. Автоматический анализ повреждений не выполняется.

Чтение данных асинхронное, с небольшой задержкой для отображения загрузки. Предусмотрены состояния загрузки, ошибки с повторной попыткой, пустой истории и отсутствия результатов поиска. При недоступности или переполнении localStorage сохранение показывает ошибку. Повреждённые данные не перезаписываются автоматически.

Вход и регистрация проверяют поля и показывают сообщение о необходимости подключения сервера. Пароли не сохраняются и не отправляются. Интеграция frontend с API остаётся для следующего этапа.

Добавлены переходы цвета этапов, появление уведомлений, предпросмотра и карточек истории, анимация диалога Material UI. Настройка prefers-reduced-motion отключает добавленные CSS-анимации.

`npm run build` проверяет TypeScript и собирает frontend. Пользовательские сценарии проверены в браузере: навигация, ошибки формы автомобиля, выбор файла, сохранение, перезагрузка истории, поиск, отмена и подтверждение удаления, пустой список, повреждённые данные и повторная загрузка, регистрация и мобильная ширина 390 px.

Скриншоты изменённых экранов находятся в [frontend/docs/screenshots](frontend/docs/screenshots): главная, автомобиль, фотография, история, пустое состояние, ошибка и мобильная версия. Навигация дополнена историей; на экране фотографии добавлена форма сохранения осмотра.
