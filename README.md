# Осмотр авто

Учебный проект по оценке повреждений подержанных автомобилей по фотографии. Работа ограничена первыми двумя лабораторными: интерфейс и серверный CRUD с PostgreSQL.

## Состав проекта

```text
frontend/             React + TypeScript, интерфейс первой лабораторной
backend/
  app/
    api/              HTTP-маршруты и зависимости
    models/           таблицы SQLAlchemy и связи
    schemas/          схемы запросов и ответов Pydantic
    crud/             операции с данными и проверки связей
    config.py         настройки из окружения и .env
    database.py       подключение, базовый класс моделей и сессии
    errors.py         ответы об ошибках
    init_db.py        создание таблиц
    main.py           приложение FastAPI
  tests/              интеграционные тесты с PostgreSQL
  .env.example        пример локальных настроек
  README.md           установка, запуск и проверка API
```

## Лабораторная №1 — frontend

Пользователь начинает осмотр, вводит марку, модель, год и тип кузова, затем выбирает фотографию автомобиля целиком. Есть отдельные формы входа и регистрации. Используются MUI, React Router, общее оформление и адаптация к ширине экрана. Данные хранятся в состоянии React до перезагрузки страницы.

Последняя версия интерфейса сохранена без изменений. Инструкции и скриншоты находятся в [frontend/README.md](frontend/README.md). Существующие скриншоты сняты до последних изменений размеров и добавления ссылок аккаунта; их нужно обновить перед сдачей.

Запуск из корня проекта:

```powershell
cd frontend
npm ci
npm run dev
```

## Лабораторная №2 — backend

Реализованы REST API на FastAPI, модели SQLAlchemy и хранение в PostgreSQL. Для пользователей, автомобилей и осмотров доступны создание, чтение списка и отдельной записи, полное изменение и удаление. Данные проверяются схемами Pydantic; предусмотрены ответы 404, 409 и 422 и обработка недоступной базы.

Связи:

```text
users (1) ─── (N) cars (1) ─── (N) inspections
```

Удаление пользователя каскадно удаляет его автомобили и осмотры. Удаление автомобиля удаляет его осмотры. Другие пользователи и их записи остаются. Удаление осмотра не удаляет автомобиль. Связи обеспечиваются внешними ключами PostgreSQL и отношениями SQLAlchemy.

Для работы нужны Python 3.12+, PostgreSQL 18 (проверяемая версия) и Node.js для frontend. pgAdmin удобен для просмотра таблиц, но не обязателен. Docker и отдельный клиент Postman не требуются: API можно проверять в Swagger по `/docs`.

Полная инструкция: [backend/README.md](backend/README.md).

## Границы реализации

- Frontend и backend запускаются отдельно. Интерфейс пока не делает запросы к API; сервер проверяется через Swagger и тесты.
- Пользователь в базе — запись с именем и почтой. CRUD пользователей не является регистрацией или авторизацией. Паролей, токенов и защищённых маршрутов нет. API предназначен для локальной демонстрации.
- Осмотр хранит имя фотографии и примечание. Файл не загружается на сервер, доступ к файлам пользователя не выполняется.
- Анализ повреждений, ML, расчёт стоимости ремонта, миграции и развёртывание не реализованы.

## Git

Эта папка — отдельная версия проекта. Исходный frontend не перезаписывается. Зависимости, `.env`, виртуальное окружение, сборка и временные файлы исключены через `.gitignore`.

В архив включён локальный Git-репозиторий этой версии с коммитом результата. Он не заменяет историю предыдущего репозитория и не отправлен на удалённый сервер.

Если переносите изменения в существующий репозиторий, сохраните его каталог `.git` и историю. Добавьте папки `frontend` и `backend`, проверьте `git diff` и создайте новый коммит.

## Проверка backend

На Python 3.12.8 и PostgreSQL 18.3 прошли 22 интеграционных теста. Отдельно проверены двукратный запуск создания таблиц, реальные HTTP-запросы к Uvicorn и сохранение пользователя, автомобиля и осмотра после перезапуска backend. Временная тестовая база отделена от пользовательских баз.
